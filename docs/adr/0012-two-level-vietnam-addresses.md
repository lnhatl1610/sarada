# ADR 0012: Use current two-level Vietnamese address selectors

- Status: Accepted
- Context: E2.1 and E2.2 need dependent address selectors. Vietnam's administrative structure removed district-level administrative units in 2025, and current address codes are published as province and commune-level units. Existing order snapshots still contain legacy district fields, and province shipping rates continue to use province codes.
- Options: (1) Keep province/district/ward inputs and require staff to enter codes manually, which does not match the current administrative structure and invites invalid codes. (2) Bundle a date-stamped province/commune catalog from the General Statistics Office's public administrative-catalog service, use it for dependent selectors, and preserve legacy district data on existing orders.
- Decision: Use option 2 for admin order editing and manual order creation. The dataset is generated from `https://danhmuchanhchinh.nso.gov.vn/DMDVHC.asmx` for 25/10/2026 and stored with the admin source. The UI selects a province then a commune/ward. New order snapshots store official province and commune codes and display names; manual-order province codes remain the input to existing province-based shipping-rate calculation. Existing district fields and old address values are retained when editing an order.
- Consequences: The selector works offline and adds about 146 KB of source data. The catalog is a snapshot and must be refreshed when the official service publishes further changes. Province shipping rates still require store staff to configure the corresponding official codes.
- Migration/rollback: No database migration is required because addresses are JSON snapshots and all new fields are additive. Rollback can restore the previous free-text/code fields; existing district data remains available.
