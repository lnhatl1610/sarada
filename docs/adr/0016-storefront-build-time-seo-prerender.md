# ADR 0016: Prerender public Storefront routes at release build time

- Status: Withdrawn (2026-11-06)
- Current state: The owner requested removal of the root and Storefront script directories. The prerender command and implementation have been removed; use the regular Vite SPA build. The original decision below is retained as historical context.
- Context: Storefront metadata and JSON-LD are currently populated by client navigation after JavaScript runs. Crawlers that do not execute the SPA can miss product, collection, CMS, and home content. Production already serves static Vite assets through Nginx and Laravel exposes a public sitemap plus read-only endpoints needed to render these routes.
- Options: (1) Move Storefront to an SSR framework/runtime, which gives request-time rendering but changes routing, hosting, caching, and operations. (2) Generate route HTML snapshots during release builds from the public API, preserving the current React SPA and static Nginx deployment, with the tradeoff that the API must be reachable during builds and snapshots refresh only on the next release.
- Decision: Keep the React/Vite SPA and add `npm run build:seo`. After the regular production build, a Node script reads the public sitemap and API, then writes initial HTML and route-specific metadata/JSON-LD for the homepage, product catalog, published products, active categories and collections, and published CMS pages. Category sitemap entries use `/categories/:slug` so static hosting can provide category-specific snapshots; existing `/products?category=...` routes stay supported. Nginx's existing `try_files` behavior serves these nested `index.html` snapshots; client-side React continues to own interactive behavior.
- Consequences: Crawlers receive useful page content without a JavaScript render. Release jobs provide `STOREFRONT_PRERENDER_API_URL` (API base ending in `/api/v1`) and `STOREFRONT_PRERENDER_SITE_URL` (public Storefront origin) through the process environment or the Storefront's `.env.production`/`.env.production.local`; process variables take precedence. The API must contain the release's intended published catalog/content. Dynamic filters, customer pages, cart, and checkout remain client-rendered. The existing `npm run build` remains suitable for ordinary local builds and CI without API access.
- Migration/rollback: To roll back, deploy the ordinary Vite build and remove the nested static route snapshots; no runtime service, schema, or migration is introduced. Snapshots can be regenerated from the deployed API on the next `npm run build:seo` release.
