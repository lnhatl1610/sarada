# ADR-0020: Frontend experience libraries

- Status: Accepted
- Context: The `lib.md` plan groups interface concerns into 20 categories and asks for one choice per category. Sarada already has two React/Vite applications, an established Tailwind/shadcn system, custom API-backed workflows, reduced-motion rules, and analytics consent. Avoid duplicate libraries for a role and prefer packages already adopted where they fit.
- Options:
  - Charts: Recharts vs Chart.js. Recharts composes React components and fits the existing React feature modules; Chart.js has a smaller imperative surface but needs wrapper/configuration patterns. Choose Recharts for Admin dashboard/report charts.
  - Video: ReactPlayer v3 vs Plyr. ReactPlayer handles direct files and supported providers in a React component; Plyr offers a polished player skin but adds another player layer and provider setup. Choose ReactPlayer, lazy-loaded only on video-bearing content; keep native controls available.
  - Tours: Driver.js vs React Joyride. Driver.js provides a small imperative tour API; Joyride offers a React-first controlled-step API but adds a second orchestration layer beside the existing account-persisted checklist. Choose Driver.js for Admin highlighting while retaining the app's existing role-specific content and persistence.
  - Maps: React Leaflet/OpenStreetMap vs a hosted Mapbox/Google map. React Leaflet needs no map token and works with the current coordinates; hosted maps offer managed geocoding/SLAs but require credentials and billing. Choose React Leaflet for the existing store directory and preserve the address list/directions as a fallback. Use a compliant tile provider and attribution.
  - Sharing: react-share vs only `navigator.share`. The browser API is compact and privacy-friendly but is not available in every desktop browser; react-share supplies provider share links/popups. Choose react-share with a Web Share fallback.
  - Feedback: keep Sonner vs add react-hot-toast. Sonner is already used by Storefront and provides the required toast behavior; a second toast package would duplicate styling and lifecycle behavior. Keep Sonner and add it to Admin.
  - Analytics: existing consent-gated GA4 (`gtag.js`) vs Clarity/PostHog. GA4 already receives the store's consent-gated ecommerce events; another behavioral provider would create overlapping collection. Keep GA4 as the single analytics provider and do not install Clarity.
  - Existing roles remain: Radix/shadcn, Motion, Embla, React Hook Form + Zod, TanStack Query, TanStack Table, Lucide, CVA, dnd-kit, Tiptap, i18next, React Router, and Playwright.
- Decision: Select one primary implementation per group as recorded in `lib.md` and `docs/architecture/frontend-architecture.md`. Install only missing packages for the selected roles: Recharts, Admin Sonner, ReactPlayer, Driver.js, React Leaflet/Leaflet, and react-share. The Storefront media wrapper builds ReactPlayer with only its HTML file player because uploads are direct MP4/WebM; this excludes unused streaming and hosted providers from the bundle. Keep GA4's current consent gate; don't add a competing analytics SDK. Use browser `Intl` for VND/date formatting and the existing SEO hook instead of a date library or Helmet. TanStack Query owns API data; React state/context is sufficient for current client UI state, so remove the unused Zustand dependency.
- Consequences: Chart, video, tour, map, and sharing capabilities get package support aligned to existing pages. The new runtime dependencies increase install size and maintenance surface; route/component-level lazy loading should limit the initial bundle. ReactPlayer v3 is a breaking major relative to v2, so implement against its current `src` API. OpenStreetMap tiles are an external service and may fail or impose usage limits; the store list and directions remain useful without them. GA4 must remain disabled until analytics consent and a valid Measurement ID are present.
- Migration/rollback: Remove a selected package and restore the current SVG/native video/iframe or browser-share implementation in the same feature if the library breaks compatibility, bundle budgets, or accessibility. ReactPlayer can be reverted to `<video>` because current uploaded media is direct MP4/WebM. Recharts can be reverted chart-by-chart to the existing SVG. Restore the existing onboarding dialog or OSM iframe if the corresponding adapter fails. No API contract or database change is required by these UI decisions.
