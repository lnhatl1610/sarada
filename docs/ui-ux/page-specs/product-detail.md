# Product Detail

## Product information and selection

- Show breadcrumb, product title, current variant price, compare-at price and exact savings amount when applicable, availability, and concise description.
- Show an exact remaining quantity only when positive available stock is at or below that variant's configured low-stock threshold; show a generic in-stock state above the threshold and an out-of-stock state at zero.
- A sold-out size opens an accessible one-time back-in-stock alert form for email, or SMS when public configuration confirms the SMS provider is configured. The API accepts only one contact method for active variants of published products, and queues the notification when available inventory returns. SMS is sent through the configured Twilio account; failed SMS jobs retry and restore the subscription for a later stock transition.
- Signed-in customers can enable or disable a product-level price-drop email alert; enabling captures the current lowest effective active-variant price as the VND baseline. Choosing a sold-out variant registers a restock email to the account address. Guests continue using the PDP email/SMS form.
- Variant selection presents color swatches with visible names and size buttons/selectors with stock state. For colored products, require an explicit color selection before showing sizes, then show only sizes for that color so duplicate size labels cannot select an ambiguous variant. Unavailable sizes are disabled and labeled “Hết hàng”; selected values remain visible and are keyboard operable.
- Selected color and size are reflected in the product URL as `?color=...&size=...`. Opening or navigating back to a valid variant URL restores its selection; changing color clears the previous size. Preserve unrelated query parameters, and ignore invalid or ambiguous variant values.
- Size guide opens an accessible dialog with measurement units and close/escape behavior. Quantity is a positive integer with decrement/increment controls, stock cap, and a direct keyboard-editable input.
- The size guide calculator uses only product-specific height/weight ranges configured by staff for sizes sold in that product. Matches are shown as suggestions, never as guaranteed fit; missing configuration yields an honest no-data state. Do not infer shopper size from variant shipping weight.
- Height entry can switch between centimetres and inches; switching units converts the entered/profile value, then converts inches back to centimetres before matching the store-configured product ranges.
- Add-to-cart remains disabled until required options are selected. On success show confirmation and cart count update; on stock/API failure keep selections and explain the issue inline.
- Product sharing offers the browser share sheet when available, direct Facebook sharing, configured Zalo sharing, and copy-link fallback. Copy/share actions announce visible success or recovery feedback.
- The PDP lists COD and manual bank transfer/VietQR only when each method is enabled by public Storefront configuration.
- Shoppers can expand a delivery estimator, choose a valid province and optional commune/ward, and see the province fallback fee plus currently eligible Admin-configured methods and their published estimate text. It clearly labels fees as estimates before cart totals/coupons; checkout remains authoritative. Province/ward lists and estimates expose loading and retryable error states.

## Media and supporting content

- Gallery supports a full-screen zoom dialog, browser pinch-to-zoom, visible zoom controls from 100% to 300%, keyboard `+`/`-`/`0` shortcuts, touch swipe navigation, explicit previous/next controls, and Left/Right arrow navigation while the dialog is open. Zoom resets when the selected image or color changes. Preserve the selected-color image set, accessible labels, and media disclosure in the dialog.
- When 24–36 ordered 360-degree frames exist for the selected color, shoppers can drag horizontally on the frame to rotate continuously, or use the keyboard-accessible range input and previous/next buttons. Vertical page scrolling remains available on touch devices; changing color resets the selected frame and active drag.

- Gallery uses store-provided photos or explicitly disclosed AI demo flat-lay photos, thumbnails, selected-color image sets, responsive crop, and accessible previous/next controls. AI photos have no people and show an `Ảnh AI demo` badge at the upper-left of the image, with alt text stating they are unverified demo concepts. If neither source is available, use a plain neutral surface without substitute artwork.
- Existing AI demo images use verified WebP candidates through width-descriptor `srcset` and reserved image dimensions. Current seeded masters are 800×1000, with existing 200×267 and 600×800 outputs; there are no 1200×1600 outputs for these masters. The Storefront optimizer was removed at the owner’s request, so the client must not infer AVIF URLs. Existing verified 360/640 candidates remain supported by the API.
- Provide Details, Materials & care, Specifications, Shipping/returns, and Reviews tabs. Tabs support arrow-key and Home/End navigation, expose the active panel to assistive technology, and keep empty states honest. Specifications use only published category, brand, fit, material, and selected-variant SKU/color/size data; absent fields stay omitted and an entirely empty specification set shows an honest no-data state. Material and care instructions come from the public product detail API. Shipping and return copy must not promise a delivery window or return period unless that policy is configured and confirmed. Reviews show approved entries only, average/count and per-star distribution when approved reviews exist, loading/empty states, a verified-purchase badge, and the purchased variant snapshot and fit feedback when present. Customers submit reviews from a delivered order's detail page; new reviews remain pending until moderation.
- Public reviews use the API's `page` parameter and pagination metadata. Previous/next controls announce the current page and total, and are disabled at either end.
- Approved reviews display the store's optional public response; responses on pending or rejected reviews are never shown in the Storefront.
- Public review responses include only the reviewer's display name; account email addresses are excluded from the Storefront contract.
- Each approved review has an accessible “Hữu ích” vote. One random browser visitor identifier can vote once per review; the API count is authoritative and duplicate requests do not inflate it.
- Review sort choices are newest first, highest rated first, and lowest rated first. Sorting is applied by the public API before pagination; changing sort returns to page one.
- Shoppers may filter approved purchase reviews by exact star rating, presence of an image, and purchased size. Size choices come from approved order-linked reviews; filters are applied before sorting/pagination, reset to page one, and provide an actionable clear-filter empty state.
- The product-detail API includes counts of approved reviews for each star rating. The PDP renders these as accessible progress bars; it does not derive full-product distribution from only the current page of reviews.
- Signed-in eligible customers can submit a rating and review; pending moderation state is explained. Ineligible users see a clear requirement or sign-in link.
- Eligible customers may attach up to five JPG, PNG, or WebP photos (2 MB each; maximum dimensions 4000×4000) and one MP4/WebM video (5 MB maximum) from the delivered-order review form. Only approved review media appears in public product reviews; moderation remains in Admin.
- Storefront product and approved-review videos use the lazy ReactPlayer wrapper with browser controls, inline playback, and metadata preload; never autoplay. The persisted uploads are direct MP4/WebM files, so they do not load third-party provider SDKs.
- Review images whose API alt text begins `Ảnh AI demo:` show the same visible disclosure in public review content; this protects a seeded demo fixture if it is ever approved during local/UAT moderation.
- Related products are loaded from the API and link to their detail pages.
- “Hoàn thiện outfit” offers up to four published, same-category related products from the API. Shoppers select individual items and an in-stock variant for each, review a VND estimate based on API variant prices, and add selected items sequentially through the cart API. The UI clearly says these are category-based suggestions, not a store-curated outfit; partial failures explain that some items may already be in the cart. Checkout/cart pricing remains authoritative.
- Product Q&A is paginated; page changes announce the current page and total question count. Public answers show the customer question and store answer only. Signed-in customers can submit a question; new questions stay private until staff with review moderation permission answers them. Pending/hidden content and customer contact data never appear publicly.
- The PDP, home page, and cart may show a recently viewed rail based on product slugs saved in this browser. Re-fetch published products before displaying them so prices and images are current; do not persist account data in this browser-only history.
- On mobile, an optional sticky add-to-cart bar respects safe-area insets, does not cover content/focus, and reflects the selected variant and price. It stays hidden on initial page load until the main add-to-cart control has entered view, appears after that control scrolls away, and hides again when the page footer enters view.

## Implementation notes

- Product detail loads from `GET /products/{slug}` independently of the paginated catalog query, with explicit loading, retry, and not-found states.
- The selected variant drives the displayed price, compare-at price, available quantity, and quantity limit. Color choices use API-provided hex swatches; gallery images have keyboard-operable previous/next controls.
- Navigating directly from one product detail URL to another resets the prior product's color, size, gallery index, and quantity selection before the new product can be added to cart.
- Recently viewed product history stores up to 12 slugs in browser local storage, deduplicates the current product, and requests the six most recent previous products from the public product API. PDP excludes the current product; home and cart show the most recent list. When signed in, the storefront merges this list with the account's server history and syncs the combined list; guests retain browser-only history. If browser storage is unavailable or products are no longer published, the page remains usable and omits unavailable entries.
- Product image and variant responses include `color_value_id`. Selecting a color filters to images associated with that catalog color while retaining shared images; products without color-specific media keep their shared gallery.
- Product detail responses expose `material` and `care_instruction`; the UI renders both fields rather than generic static claims. Demo seed values are visibly marked as illustrative and require confirmation against actual stock before production use.
- Shipping/returns copy loads from the published public CMS page with slug `shipping`; the size guide loads from `size-guide` only when opened. Both use the existing query cache, expose loading/error/unpublished states, and sanitize the returned HTML before display. The demo seeder publishes an explicitly labeled size-measurement example, not a claim about actual garment measurements.
- Delivery estimates load only when the PDP estimator is opened. `GET /shipping/fee` returns the province-rate fallback, threshold, and active destination-eligible delivery methods; selecting a ward also includes methods limited to that ward. The PDP labels these as informational because cart value and coupons may change the final fee at checkout.
- Product responses expose SEO title/description fields. The detail page applies them to document and social metadata and publishes Product, AggregateOffer, AggregateRating, and approved Review JSON-LD from public product, inventory, and review data. Up to three latest approved reviews are included in the product detail response for this markup and appear in prerendered product content. The home page publishes Organization/WebSite/SearchAction data.
- Product title fallbacks and Product brand fallback use the public Storefront `store_name`; configured product SEO metadata still takes precedence.
- Product images use descriptive alt text for store photos and AI demo photos; a missing or failed image is represented by a plain neutral surface.
- Storefront `Product` and `StorefrontReview` types come from the generated OpenAPI contract; the contract describes fields returned by Laravel's `ProductResource` and `ReviewResource`, including rating summaries and paginated approved-review responses. Client-side route changes update canonical and Open Graph URLs together.
- Color-specific gallery images are used only when the store supplies matching photography for that color. AI demo flat-lays are generic product concepts and do not claim to represent a specific color/stock variant; absent matching media, show a neutral color-update state rather than reusing a misleading image.
- Size guidance opens a native dialog with Escape and close-button support. Cart requests are sent before the local cart is updated; API errors remain visible beside the add button and preserve the current selections.
- On narrow viewports, an intersection-aware purchase bar appears after the main add button has been seen and then leaves view; it stays hidden before the shopper reaches the primary purchase control and when the footer enters view. It follows the selected variant and price, respects the device safe area, and hides while a control on the product page has focus.

## Acceptance criteria

- [x] Product photos open in a keyboard-accessible full-screen dialog; pinch zoom, touch swipe, and explicit image navigation follow the selected image.

- [x] Variant, quantity, availability, and price stay synchronized; client totals remain display-only.
- [x] Gallery controls and size guide are keyboard accessible; product information uses keyboard-operable Details, Materials & care, Specifications, Shipping/returns, and Reviews tabs.
- [x] Missing images, no reviews, unavailable variants, product loading, and detail API errors have explicit states.
- [x] Approved product reviews follow server pagination with accessible previous/next controls and visible page/total metadata.
- [x] PDP, home, and cart show up to six recently viewed, still-published products from browser-local slug history, using fresh API product details.
- [x] Signed-in customers merge browser and account recently viewed slugs; account history is private to the authenticated customer and limited to currently published products.
- [x] Add-to-cart errors are actionable and do not clear valid selections.
- [x] PDP includes an outfit-selection panel with up to four API-related in-stock products, explicit variant selection, estimated total, sequential add-to-cart, and partial-success feedback.
- [x] Color-specific image associations are supported by the API and gallery. Matching store photos may be shown by color; AI demo photos are disclosed and are not treated as verified color/stock imagery. Missing color-specific media uses the neutral color-update state.
- [x] Mobile sticky add-to-cart bar follows the selected variant, respects safe-area insets, and yields while product controls have focus.
- [x] PDP delivery estimator loads province/ward-scoped methods on request, shows only configured fee/ETA data, labels fees as estimates, and provides retryable loading/error states.
- [x] Signed-in PDP customers can inspect/toggle a product price alert; a lower effective price sends one queued email, and sold-out variant selection registers a restock email.
- [x] Product Q&A shows answered questions with pagination, accepts authenticated customer questions, and allows authorized staff to answer or hide them.
