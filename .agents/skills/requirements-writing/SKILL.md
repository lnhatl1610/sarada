# Requirements Writing

1. Read `docs/requirements/README.md`, `vision-scope.md`, and related domain docs.
2. Assign an unused immutable FR/NFR/BR ID using the repository scheme; never recycle an ID.
3. Write normative, verifiable language, priority, acceptance evidence, source, linked spec, and status.
4. Update glossary for new domain language, user stories when personas change, and traceability for every affected ID.
5. If behavior changes, update requirement first, then spec, API/UI docs, and implementation.
6. Record unresolved decisions in `open-questions.md` with an assumption and impact.

Use `references/requirement-template.md` as the entry template.
